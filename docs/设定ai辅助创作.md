# 设定集 · AI 辅助创作

> 目标：让"设定集"从"手动抄书"变成"和编辑一起写"。生成的一切都先落在草稿框里，**人确认后才写库**。

---

## 1. 入口

| 入口 | 位置 | 用途 |
|---|---|---|
| **AI 生成** | 设定集页右上角（与「导入 Markdown」并排） | 新建一张卡，或从下拉里选一张已有卡扩写 |
| 扩写模式 | 对话框内「扩写已有」页签 | 选卡 → 读原正文 → 在保留信息的前提下补细节 |

沿用当前调用模式（`local` / `api` / `paste`）：非粘贴模式直接调模型；粘贴模式只生成**提示词**，你复制到网页 AI，再把回复贴回预览框。

---

## 2. 交互流程

```
点「AI 生成」
  ├─ 新建：标题 + 分类 + 一句话要求 + 篇幅 + 语气
  └─ 扩写：选卡（自动带上原正文与标题）
        ↓  生成草稿
     提示词（可展开/复制）  ← 粘贴模式下这里是唯一产物
        ↓
     草稿编辑框（可直接改，也可先自己写再让 AI 续）
        ↓
  ┌─ 新建 → 「保存为新卡片」→ create_lore_card（写 .md + 切片段 + 建元数据）
  └─ 扩写 → 「写回原卡片」（覆盖正文，保留标题/分类/标签）
            └「另存为新卡」（原卡不动，标题加「·扩写」）
```

关键约束：**对话框关掉之前不改任何文件**；写回原卡也不删除旧内容的备份（如需要，用「另存为新卡」）。

---

## 3. 接口

| 命令 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `lore_ai_generate` | `req: LoreAiRequest` | `LoreAiResult { prompt, text, mode }` | 非粘贴模式返回生成正文；粘贴模式 `text` 为空 |
| `create_lore_card` | `world_id, category_id?, title, content` | `doc_id` | 一次事务完成：写 `.md`、切片段、写 `lore_cards`、同步 FTS |

内部复用：

- `engine::complete(profile, prompt, max_tokens, temperature)` —— 新增的一次性补全（非流式），与回合生成共用 `engines.yaml` 的地址/模型/超时。
- `lore::create_doc` / `lore::save_doc` / `lore::reslice_and_update` —— 沿用既有的原子写 + sha256 + 切片逻辑。
- `diagnostics::log("lore_ai", …)` —— 记录模式、标题、字数，便于回看。

## 4. 数据结构

### 4.1 请求 / 结果

```rust
pub struct LoreAiRequest {
    pub world_id: String,
    pub title: String,              // 新建：卡名；扩写：忽略（用原卡名）
    pub brief: String,              // 一句话要求，可空
    pub category_id: Option<String>,// 新建时的分类
    pub expand_doc_id: Option<String>, // 扩写目标
    pub length: Option<String>,     // short | medium | long
    pub tone: Option<String>,       // canon | plain | epic
    pub mode: Option<String>,       // local | api | paste
}

pub struct LoreAiResult { pub prompt: String, pub text: String, pub mode: String }
```

### 4.2 存储

**没有新增表**。生成结果保存后完全走既有结构：

| 表 | 写入内容 |
|---|---|
| `lore_docs` | 标题、`rel_path`、sha256、`origin` |
| `lore_cards` | `category_id`、`summary`（正文前 80 字）、`char_count` |
| `lore_chunks` | 由 `reslice` 按标题切分 |
| `lore_fts` | 切片后自动补索引（`sync_fts`） |
| 文件 | `worlds/<world>/lore/<slug>.md`，内容是 `# 标题` + 正文 |

> 草稿本身不落库——关掉对话框就丢弃。这是刻意的：不想在库里堆"半成品"。

## 5. 提示词结构

```
你是中文小说的设定编辑，只输出 Markdown 正文…
【世界观】名称
【既有背景】世界事件背景（截断 1200 字）
【已有分类】全部分类名
【已有条目】最近 40 张卡标题
【待扩写的条目】《标题》+ 原正文（截断 3000 字）   ← 仅扩写模式
【本次任务】新写一张… / 在保留原有信息前提下扩写… + 所属分类 + 作者要求
篇幅：300–500 / 600–900 / 1000–1500 字。语气：考据/通俗/热血。
【格式】直接正文；可用 ### 小标题、列表、粗体；不要一二级标题、不要客套话
```

放在同一个 prompt 里而不是分两步：设定卡通常 300–1500 字，一次生成足够；分步会让本地模型多花一倍时间。

`max_tokens` 按篇幅给：短 700 / 中 1300 / 长 2200。

## 6. 边界情况

| 情况 | 处理 |
|---|---|
| 标题为空（新建） | 前端拦截；后端 `build_prompt` 也返回「标题不能为空」 |
| 世界观不存在 | 返回「世界观不存在」 |
| 卡片正文为空 | 拒绝保存（「正文为空，没什么可保存的」） |
| 同名卡片已存在 | `create_lore_card` 自动加序号「（2）」「（3）」，最多 20 次，不打断流程 |
| 扩写目标被删了 | `build_prompt` 返回「要扩写的卡片不存在」 |
| 模型未配置 | 返回「engines.yaml 里没有 x 模式的配置」，提示切模式 |
| 模型返回空 | 「模型返回了空内容，换个要求或降低篇幅再试」 |
| 返回带代码围栏 / 「以下是…」 | `tidy()` 去围栏、去开场白，最多保留 8000 字 |
| 返回含 `# 标题` | 提示词已禁止；若仍出现，保存时会与原 `# 标题` 重复，需手动删（已知小瑕疵） |
| 超时 / 断网 | 沿用 `engines.yaml` 的 `timeout_ms`；错误原样抛给 toast，草稿框内容保留 |
| 粘贴模式 | 只出提示词；贴回的文本直接进草稿框，可再编辑 |
| 扩写覆盖原卡 | 前端先读最新 sha 再保存（`force=true`），避免与外部编辑冲突；另提供「另存为新卡」 |
| 分类被删 | `category_id` 写库时置空，卡片落到「未分类」 |
| 结果过长挤爆上下文 | 这是**独立调用**，不占回合上下文；入库后才按正常的设定注入规则参与检索 |

## 7. 已知限制 / 后续

1. **没有流式**：一次性返回，长文要等十几秒。要做流式需复用 `stream_chat` 并把增量渲染进草稿框。
2. **没有多轮**：不能在对话框里"再改改这一段"。可行做法是把草稿作为下一轮的 `expand` 输入。
3. **不能批量**：一次一张卡。批量需要队列 + 进度 + 失败重试。
4. **无版本历史**：写回原卡是覆盖。彻底解决要给 `lore_docs` 加历史表（或复用 backups 目录）。
5. **入口只有工具栏**：后续可在卡片右键/编辑器里加「AI 扩写这张」直接带上下文打开。
